# Stage06A — bounded offline outcome chronology (initial implementation)

Authority: [Issue #51 owner #6890458361](https://github.com/scannercrypto0-gif/zs-crypto-signals/issues/51#issuecomment-6890458361). Based on approved Stage06A design in main MASTER (outcomes after provable availability only, NO_ENTRY, same-bar ambiguity, no look-ahead). Development-only on a pinned approved main base; upstream Stage05 PR dependencies remain unmerged.

- Pure `Decimal` long/short *research-only* entry/stop/target evaluator. Requires explicit timezone-aware UTC timestamps for signal availability, observed `as_of` and source-available finalized candles. Rejects missing/future/unclosed/invalid data. Only entire bars starting after recorded availability are evaluated; the intersecting bar is omitted and marked as left-censored in the result note.
- Never invents intrabar order, execution fill, realized P&L, scientific win rate, trade authority or a `signal_id`. Same entry/exit bar is `AMBIGUOUS_ENTRY_BAR`; simultaneous target and stop in a later bar is `AMBIGUOUS_EXIT_BAR`. Gaps, insufficient history, unresolved entry, and no-entry remain distinct.
- No HTTP, Telegram, market requests, SQL writes, scheduler or production code paths. No existing Stage00–05 contracts changed. This is an initial 06A slice, **not full Stage06 closure**; 06B export/SQL checks, pipeline adapter, source publication time and historical/forward separation remain subsequent implementation work.
